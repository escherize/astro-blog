Serdes Export: Before & After

GHY-3385 / batch cache for *export-field-fk* and *export-table-fk*

Every card carries result_metadata - a JSON array describing every column. During export, each column triggers individual DB queries to resolve field hierarchies, table names, and database names. The batch cache replaces this with preloading - on first miss, load the entire table's fields and FK-connected tables in one go.

Before CURRENT

Each column in result_metadata triggers 3-4 individual DB queries. The with-cache macro memoizes by exact ID, but each unique field still causes a fresh recursive CTE. No spatial locality - no awareness that fields on the same table will be needed next. 

sequenceDiagram
    participant E as extract-one
    participant RM as export-result-metadata
    participant EF as *export-field-fk*
    participant FH as field-hierarchy
    participant ET as *export-table-fk*
    participant DB as Application DB

    E->>RM: card.result_metadata

    loop For each column (N times)
        RM->>EF: column :id (field_id)
        EF->>FH: field_id
        FH->>DB: Recursive CTE query
        DB-->>FH: [field, parent, ...]
        FH-->>EF: field chain
        EF->>ET: table_id
        ET->>DB: SELECT table
        DB-->>ET: table row
        ET->>DB: SELECT database
        DB-->>ET: db row
        ET-->>EF: [db, schema, table]
        EF-->>RM: [db, schema, table, field]

        RM->>EF: column :fk_target_field_id
        EF->>FH: fk_field_id
        FH->>DB: Recursive CTE query
        DB-->>FH: [field, parent, ...]
        FH-->>EF: field chain
        EF->>ET: table_id
        ET->>DB: SELECT table
        DB-->>ET: table row
        ET->>DB: SELECT database
        DB-->>ET: db row
        ET-->>EF: [db, schema, table]
        EF-->>RM: [db, schema, table, fk_field]

        RM->>ET: column :table_id
        ET->>DB: SELECT table
        DB-->>ET: table row
        ET->>DB: SELECT database
        DB-->>ET: db row
        ET-->>RM: [db, schema, table]
    end

    Note over DB: ~50 DB queries per card
~25,000 total for 500 cards
The memoize cache helps, but not much. Different cards reference different fields, so cache hit rate is low on the first pass through each table's fields. The recursive CTE is the expensive part - and it runs once per unique field ID, sequentially.

After BATCH CACHE

On first cache miss, batch-load-fields loads the requested field's hierarchy plus all fields from the same table and FK-connected tables. Subsequent columns from the same table are instant cache hits. The batch cache sits between the export functions and the DB - the export API is unchanged. 

sequenceDiagram
    participant E as extract-one
    participant RM as export-result-metadata
    participant EF as *export-field-fk*
    participant FC as Field Cache
    participant TC as Table Cache
    participant DC as DB Cache
    participant DB as Application DB

    E->>RM: card.result_metadata

    rect rgba(21, 128, 61, 0.05)
    Note over FC,DB: First column triggers batch preload
    RM->>EF: column :id (field_42)
    EF->>FC: lookup field_42
    FC-->>FC: MISS
    FC->>DB: batch-load-fields: CTE + same table + FK tables
    DB-->>FC: {field_42: ..., field_43: ..., field_44: ..., ...}
    FC-->>EF: field_42 data
    EF->>TC: lookup table_7
    TC-->>TC: MISS
    TC->>DB: batch-load-tables: table_7 + FK-connected tables
    DB-->>TC: {table_7: ..., table_8: ..., table_12: ...}
    TC-->>EF: table_7 data
    EF->>DC: lookup db_1
    DC-->>DC: MISS
    DC->>DB: batch-load-databases: db_1 + others
    DB-->>DC: {db_1: ..., db_2: ...}
    DC-->>EF: db_1 data
    EF-->>RM: [db, schema, table, field]
    end

    rect rgba(21, 128, 61, 0.12)
    Note over FC,DB: Remaining columns are cache hits
    loop For each remaining column
        RM->>EF: column :id (field_43)
        EF->>FC: lookup field_43
        FC-->>EF: HIT
        EF->>TC: lookup table_7
        TC-->>EF: HIT
        EF->>DC: lookup db_1
        DC-->>EF: HIT
        EF-->>RM: [db, schema, table, field]

        RM->>EF: column :fk_target_field_id
        EF->>FC: lookup fk_field
        FC-->>EF: HIT (preloaded via FK tables)
        EF->>TC: lookup fk_table
        TC-->>EF: HIT (preloaded via FK tables)
        EF-->>RM: [db, schema, table, fk_field]

        RM->>EF: column :table_id
        EF->>TC: lookup table
        TC-->>EF: HIT
        EF-->>RM: [db, schema, table]
    end
    end

    Note over DB: ~3 DB queries for first column
~0 for remaining columns on same table
Spatial locality pays off. Cards on the same database share table and DB cache entries. Cards querying the same table share field cache entries. FK-connected tables are preloaded because result_metadata frequently contains FK target fields. The cache evicts old entries beyond 50k to cap memory.
