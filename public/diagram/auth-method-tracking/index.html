How auth_method Gets Tracked

PR #71386 · enhance-usage-analytics-for-embedding

Three authentication scenarios, traced from the initial request through the middleware chain to the final auth_method value written to view_log / query_execution. Each step links to the source on the branch.

1

Session Created via JWT SSO

A customer's app redirects the user to Metabase's SSO endpoint with a signed JWT token. Metabase validates the token, creates a session linked to the JWT provider, and sets a session cookie. On subsequent requests, the session's auth provider ("jwt") flows through to auth_method.

Login Endpoint
User hits GET /auth/sso with a jwt query param. The SSO route handler dispatches to the JWT integration.
sso/api/sso.clj:37-44
JWT Validation
session-data calls auth-identity/login! :provider/jwt, which decodes the token, verifies the signature against the JWT shared secret, and extracts user info (email, groups).
sso/integrations/jwt.clj:19-37 → providers/jwt.clj:80-133
Session + AuthIdentity Created
create-session-with-auth-tracking! creates an auth_identity row with provider = "jwt" and a core_session row with auth_identity_id FK. A session cookie is set on the response.
auth_identity/session.clj:15-41
Subsequent Request: wrap-current-user-info
On next request, session-with-id-query JOINs auth_identity to get provider as :auth-provider. merge-current-user-info sets :auth-method on the request to (or (:auth-provider session-info) "session"), which resolves to "jwt".
session.clj:109 (JOIN), session.clj:242 (auth-method)
bind-current-user
Binds *auth-method* dynamic var to (:auth-method request), which is "jwt". The or short-circuits - route fallback is never reached.
session.clj:283-285
include-sdk-info → DB
include-sdk-info reads *auth-method* and writes it to the row's :auth_method column via before-insert hooks on ViewLog and QueryExecution.
sdk.clj:97
auth_method: "jwt"
embedding_route: nil
embedding_client: nil (or SDK header if present)
2

API Key in the Header

An automated client sends the X-Api-Key header. There's no session - the API key is validated directly on every request by looking up the key prefix and verifying the bcrypt hash.

Header Extraction
merge-current-user-info destructures x-api-key from the request headers. No session is found, so it falls through to API key validation.
session.clj:239
API Key Validation
current-user-info-for-api-key validates the key format via Malli schema, looks up the user by key prefix (user-data-for-api-key-prefix-query), then verifies the full key against the stored bcrypt hash via matching-api-key?. Timing-safe: uses do-useless-hash on miss to prevent timing attacks.
session.clj:214-236 (validation), session.clj:207-212 (hash check)
auth-method = "api-key"
merge-current-user-info hits the api-key-info branch and hardcodes auth-method to "api-key".
session.clj:243
bind-current-user
Binds *auth-method* to "api-key" from (:auth-method request). Route fallback not reached.
session.clj:283-285
include-sdk-info → DB
*auth-method* = "api-key" is captured into the DB row.
sdk.clj:97
auth_method: "api-key"
embedding_route: nil
embedding_client: nil (or SDK header if present)
3

Signed JWT via /api/embed/* (Guest Embed)

An iframe or SDK loads a card/dashboard via /api/embed/card/:token/query. The token is a JWT signed with the embedding secret key (completely separate from SSO JWT). No session or API key is involved. The guest-embed JWT is the authorization mechanism - it determines what the client can see and with what filters.

embedding-mw: Route Detection
embedding-mw matches the URI prefix /api/embed/ against route-surface-mapping and binds *route* = "guest-embed". Also reads X-Metabase-Client header into *client* (e.g. "embedding-iframe-static").
sdk.clj:117-124 (mapping), sdk.clj:133-160 (middleware)
Embed JWT Validation (in handler)
The embed handler calls unsign-and-translate-ids, which calls embedding.jwt/unsign. This verifies the token against the embedding-secret-key setting (NOT the SSO JWT secret). Extracts the card/dashboard ID, locked parameters, and unsigned token claims.
embed.clj:61-65 (unsign call), embedding/jwt.clj:28-44 (verification)
wrap-current-user-info: Nothing Found
No session cookie, no X-Api-Key header. session-info and api-key-info are both nil. auth-method on the request stays nil.
session.clj:240-243
bind-current-user: Route Fallback
(:auth-method request) is nil, so the or falls through. ({"guest-embed" "guest"} (get-route)) maps "guest-embed" to "guest". Binds *auth-method* = "guest".
session.clj:283-285
include-sdk-info → DB
All three dynamic vars are captured into the DB row: *auth-method* = "guest", *route* = "guest-embed", *client* = whatever the embedding client sent.
sdk.clj:89-98
auth_method: "guest"
embedding_route: "guest-embed"
embedding_client: "embedding-iframe-static" (or other client header)
