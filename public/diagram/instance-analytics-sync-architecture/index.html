Three Startup Phases

Each phase builds on the previous one. Migrations create the raw DB objects, YAML loading populates the dashboards and cards, and schema sync makes the new columns visible to those cards.

Phase 1
Liquibase Migrations
Migrations add columns to raw tables and create versioned SQL views. Each view has three variants - one per supported DB engine.
  1. addColumn changesets add columns to view_log and query_execution
  2. sqlFile changesets create/replace SQL views (e.g. v_query_log)
  3. Views are versioned in folders: v1/, v2/, v3/, v4/, v5/
  4. Computed columns like surface are CASE expressions in the view SQL

Phase 2
Serialized YAML Loading
On startup, ensure-audit-db-installed! copies YAML content from the jar to the plugins directory, then deserializes it into the app database if the checksum has changed.
ia-content->plugins → checksum? → adjust-to-source! → v2-load-internal! → adjust-to-host!
  1. v2.ingest/ingest-yaml walks the directory, reads .yaml files into maps with :serdes/meta
  2. v2.load/load-metabase! inserts cards, dashboards, collections into the app DB
  3. adjust-audit-db-to-host! converts schema types to match the host engine
enterprise/audit_app/audit.clj resources/instance_analytics/collections/ enterprise/serialization/v2/ingest.clj
Phase 3
Schema Sync
After loading content, runs sync-database! {:scan :schema} on the Internal Metabase Database. This introspects SQL views and creates Field records for every column - including new ones added by migrations.
  1. Introspects all views in the audit database
  2. Creates/updates Field records for each column
  3. Normalizes types to match the host DB (e.g. postgres timestamptz becomes mysql datetime)
  4. Cards can now query the new columns

Runtime
Data Population
At runtime, include-sdk-info in sdk.clj populates the underlying raw columns on every view_log and query_execution insert. The SQL views then compute derived columns like surface.
  1. embedding-mw captures route + client from URI/headers
  2. bind-current-user resolves auth_method from session/API key/route
  3. include-sdk-info merges all analytics fields into the DB row
  4. SQL view CASE expression computes surface from embedding_route + embedding_client

Development
Editing Analytics Content
The YAML files are the source of truth, but you don't edit them by hand. Instead, use the mage workflow to edit dashboards in the Metabase UI and export them back.
mage analytics:setup → Edit in Metabase UI → mage analytics:finalize → YAML exported
