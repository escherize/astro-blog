Source Replacement Compilation Tracker

In-situ regression detection across upgrade and swap phases

1 — Three-Phase Compilation Flow

The tracker instruments run-swap* at three checkpoints. At each one, every card dependent is compiled to detect regressions introduced by that specific phase.

0
Checkpoint: Before Upgrade

Compile all card dependents. This is the baseline — any card that fails here is a pre-existing issue and will be ignored.

;; runner.clj — before phase 1 loop (when *compilation-tracker* (*compilation-tracker* :before-upgrade card-entities))
1
Phase 1: Upgrade Field Refs

Runs field-refs/upgrade! on every entity. Converts ID-based field refs to name-based refs.

  • card-upgrade-field-refs! — dataset_query + viz settings
  • dashboard-upgrade-field-refs! — parameter mappings + column settings
  • transform/segment/measure-upgrade-field-refs!
✓
Checkpoint: After Upgrade

Compile all cards again. Diff against baseline: any card that compiled before but fails now is an upgrade regression.

;; runner.clj — after phase 1 loop, before phase 2 (when *compilation-tracker* (*compilation-tracker* :after-upgrade card-entities))
2
Phase 2: Swap Sources

Runs source-swap/do-swap! on every entity. Rewrites source-table/source-card references and remaps all field refs.

  • card-swap! — dataset_query + table_id + dashcard viz
  • swap.mbql/swap-mbql-stages + swap.native/update-native-stages
  • dashboard-swap! — parameter mappings + column settings
✓
Checkpoint: After Swap

Compile all cards a final time. Diff against post-upgrade: any card that compiled after upgrade but fails now is a swap regression.

;; runner.clj — after phase 2 loop (when *compilation-tracker* (*compilation-tracker* :after-swap card-entities))
2 — Regression Detection Logic

A card's compilation status is tracked across all three checkpoints. Only transitions from compilable to non-compilable are captured as regressions.

Scenario Before Upgrade After Upgrade After Swap Classification Captured?
Happy path compiles compiles compiles No regression no output
Upgrade broke it compiles FAILS FAILS Upgrade regression :regressions :upgrade
Swap broke it compiles compiles FAILS Swap regression :regressions :swap
Pre-existing failure FAILS FAILS FAILS Not our problem ignored
Swap fixed it FAILS FAILS compiles Bonus fix not tracked
Upgrade broke, swap fixed compiles FAILS compiles Upgrade regression (self-healed) :regressions :upgrade
Key insight: The after-upgrade checkpoint diffs against before-upgrade. The after-swap checkpoint diffs against after-upgrade (not baseline). This means each regression is attributed to exactly one phase.
3 — Data Flow: Dynamic Var Bridge

swap_verify.clj (dev) creates the tracker and binds it; runner.clj (enterprise) calls it at checkpoints. The dynamic var *compilation-tracker* is the bridge between them.

swap_verify.clj (dev)

  • Creates results-atom
  • Creates tracker-fn (callback)
  • Binds *compilation-tracker*
  • Calls runner/run-swap
  • Reads @results-atom after return
  • Writes EDN report file

4 — EDN Report Structure

Output file: swap_report_<card-id>_<sha>_<date>.edn. The filename encodes what was tested, on which commit, and when — making it easy to compare across runs.

:regressions — what broke
{:regressions {:upgrade [{:card-id 789 :card-name "Revenue by Month" :error {:message "No matching clause :expression" :ex-data {:clause [:expression ...]} :stacktrace ["at clojure.core..." "at metabase.lib..." ...]}}] :swap [{:card-id 123 :card-name "Orders Dashboard" :error {:message "Invalid source-card" ...}}]}}
:stats — the scoreboard
{:stats {:before-upgrade {:compilable 45 :failing 3} :after-upgrade {:compilable 44 :failing 4} :after-swap {:compilable 42 :failing 6}} :elapsed-ms 12340 :old-source [:card 46] :new-source [:card 999]}
Stats tell the story at a glance. If :compilable drops between checkpoints, that phase introduced regressions. If it stays flat, that phase is clean.
5 — Analyzing Results
Correctness

Goal: zero regressions.
Group regressions by :message to find error buckets. Each bucket is a distinct bug class to fix.

;; find error buckets (frequencies (map #(get-in % [:error :message]) (concat (:upgrade regressions) (:swap regressions))))

Output: {"No matching clause" 8, "Invalid base type" 5, ...}

Performance

Track :elapsed-ms across commits.
The SHA is in the filename — diff performance between commits to catch slowdowns.

;; compare runs across SHAs (def runs (map #(clojure.edn/read-string (slurp %)) (glob "swap_report_46_*.edn"))) (map (juxt :sha :elapsed-ms) runs)
Progress

Track compilable count over time.
As you fix bugs, :compilable in :after-swap should trend upward.

;; trend: compilable after swap (map (juxt :sha #(get-in % [:stats :after-swap :compilable])) runs) ;; => [["abc123" 42] ;; ["def456" 44] ;; ["ghi789" 48]]
Phase attribution matters. If most regressions are in :upgrade, the problem is in field-refs/upgrade! — likely bad field ref resolution or missing expression metadata. If they're in :swap, the problem is in source-swap/do-swap! — likely bad source/field mapping or native SQL rewriting.

Single model test
;; Run against one model (auto-clone) (sv/run-verified-swap! [:card 46]) ;; → prints only regressions (if any) ;; → writes swap_report_46_abc123_20260302.edn
Batch bench
;; Run across many models (sv/run-swap-bench [6736 16995 4872 12339]) ;; → one report file per model ;; → aggregate summary printed
Aggregate error buckets
;; Load all reports, bucket errors (def reports (map #(clojure.edn/read-string (slurp %)) (file-seq-matching "swap_report_*.edn"))) (def all-errors (mapcat #(concat (get-in % [:regressions :upgrade]) (get-in % [:regressions :swap])) reports)) (frequencies (map #(get-in % [:error :message]) all-errors))
Phase-specific investigation
;; Which cards break ONLY during swap? (def report (clojure.edn/read-string (slurp "swap_report_46_abc_20260302.edn"))) ;; Swap regressions with full stacktraces (doseq [{:keys [card-id card-name error]} (get-in report [:regressions :swap])] (println card-id card-name) (println (:message error)) (doseq [line (:stacktrace error)] (println " " line)) (println))
Decision framework

Most regressions in :upgrade?

Fix field-refs/upgrade! — field resolution, expression metadata, viz settings conversion.

Most regressions in :swap?

Fix source-swap/do-swap! — source mapping, field ID remapping, native SQL rewriting.

Zero regressions?

Ship it. The swap is safe for this model and all its dependents.
