From Postgres-only to driver-agnostic table addressing

We started from a question about MySQL isolation, ended with two pushed commits that unify how every supported warehouse expresses the level above :table. The config.yml wire format and the storage rows now speak the same shape. Snowflake and SQL Server cross-DB workspaces are expressible end-to-end for the first time.

The original config.yml contract assumed Postgres: every workspace database had a single source schema and a single output schema. That model can't represent ClickHouse "databases" sitting at AST :schema, MySQL's zero-level cardinality, or Snowflake / SQL Server / BigQuery's true 3-part identifiers. Two commits fixed it.

02

Two commits, one story

b447fc19a4b Populate :db slot for Snowflake / SQL Server

Both drivers' qualified-name-components declared [:db :schema], but db-position-value only branched on BigQuery — so :db fell through to nil and normalized to "". The from-side slot that should have held the warehouse database name stayed empty. Closes the from-side of audit gap H7.

Added an addressing-truth-table test (3 deftests, 8 drivers) that turns the canonical addressing-scheme doc into executable spec. The test caught the gap on the all-drivers run before either of us went looking.

a41175fa492 Switch config.yml to driver-agnostic ::table-namespace

Replaced input_schemas: [string] / output_schema: string with input: [{db?, schema?}] / output: {db?, schema?}. Slots are AST positions, not warehouse vocabulary. nil / missing means "this driver doesn't populate this level"; "" is rejected on the wire (only valid at storage).

Hard cutover, no compat shim. Loader now emits the new atom shape; new db-workspace-namespace reader returns {:db ?, :schema ?}; add-transform-target-mapping! populates both slots on the to-side. Closes the to-side of audit gap H7. End-to-end cross-DB workspace remapping is now structurally complete.

03

The wire-format change

Before — Postgres-shaped retired 
workspace:
  databases:
    test-data (postgres):
      input_schemas:
      - public
      output_schema: mb_isolation_44490_1933
After — namespace-shaped shipped 
workspace:
  databases:
    test-data (postgres):
      input:
      - schema: public
      output:
        schema: mb_isolation_44490_1933
— same Postgres example, two contracts —

The Postgres case is the trivial case of the new shape. The new contract earns its keep on drivers the old one couldn't represent at all. A Snowflake workspace can now say output: {db: WS_DB, schema: WS_ALICE}; BigQuery output: {db: project, schema: dataset}; MySQL can leave input: [{}] empty and still produce a valid 1-level output (the cardinality-upgrade case).

05

Five invariants the new contract upholds

INV-1
One shape, one funnel
spec-for-table is the only producer; loader, atom, reader, and consumer all speak the same map.
INV-2
Slots are AST positions
:db ↔ catalog, :schema ↔ db, :table ↔ name. Not warehouse vocabulary.
INV-3
"" at storage, missing on wire
Empty-string sentinel keeps the unique constraint enforceable; nil/missing on the wire is the contract.
INV-4
No fourth slot
SQL grammar caps at three. Account, region, credentials live in connection details, not the addressing scheme.
INV-5
qualified-name-components is law
Authoritative for which slots a driver populates. The new tests pin every row of the doc against the multimethod's actual return value.
