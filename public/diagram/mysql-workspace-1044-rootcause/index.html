CI failure root-cause memo

MySQL/MariaDB workspace iso user gets 1044 at JDBC handshake

`Access denied for user 'mb__isolation_*'@'%' to database 'test-data'` — not a permission bug, a test-shape divergence. Three things have to align: bound DB, input list, and the grant the iso user actually receives.

java.sql.SQLSyntaxErrorException:
  (conn=388) Access denied for user 'mb__isolation_6f4a3_968578356'@'%' to database 'test-data'
SQLState: "42000"  errorCode: 1044

1What happens at JDBC connect

MySQL Connector/J sends a connect packet with username, password, AND a default database (from jdbc:mysql://host/test-data). The server runs two ACL checks before the handshake completes: 

sequenceDiagram
    participant J as JDBC driver
    participant S as MySQL server
    participant U as mysql.user
    participant D as mysql.db

    J->>S: handshake: user=iso, password=***, db=test-data
    S->>U: lookup ('iso', '%')
    U-->>S: found, password ok
    Note over S: user auth: ✓
    S->>D: lookup row for ('iso', 'test-data', '%')
    D-->>S: NO row exists
    Note over S: DB-access: ✗
    S-->>J: ERROR 1044 (42000): Access denied to db 'test-data'
    Note over J,S: connection rejected before any USE / query

The DB-access check passes if any row exists in mysql.db for that (user, host, db) tuple — flag values don't matter, presence does. No row → 1044. The grant logic is what either writes that row or doesn't.

3Test shape: input != bound

The driver-isolation tests create a fresh per-run MySQL DB (mb_iso_in_<run-id>) as the workspace input. That divergence exists for a Redshift reason — Redshift's public schema has CREATE granted to PUBLIC by default, breaking the input-deny contract — but MySQL has no analogous default-grant problem.

4Why my GRANT USAGE fix didn't take

Commit 64959c0083c added one statement to init-workspace-isolation! intending to write a placeholder mysql.db row covering the bound DB: 

;; in init-workspace-isolation! :mysql
(format "GRANT USAGE ON %s.* TO `%s`@'%%'"
        (sql.u/quote-name :mysql :schema bound-db) user)
why this is a no-op MySQL treats GRANT USAGE at db scope as "no privileges" — and writes nothing. The server does not insert a mysql.db row when every flag would be N. The grant statement succeeds, but SHOW GRANTS and mysql.db are unchanged. The 1044 still fires at handshake because the DB-access check still finds nothing for (iso, test-data). My comment in that commit was factually wrong on this point.

The only way USAGE creates a row is at global scope (GRANT USAGE ON *.*), which is set implicitly by CREATE USER anyway — and a global USAGE row doesn't satisfy a per-DB ACL check. There's no syntax for "no-op grant on one specific db."

The MySQL "schema" concept doesn't exist — a MySQL input_schemas entry IS a database name. The only meaningful prod case is "the customer's bound DB is also their workspace input," because there's no schema-within-DB to narrow further. So input == bound is the only shape MySQL/MariaDB customers can ship.

6The fix

Revert the USAGE grant

Drop the cond-> branch in init-workspace-isolation! :mysql. The statement is a no-op; the explanatory comment is factually wrong. Restore the original 3-statement shape (CREATE DATABASE / CREATE USER / GRANT ALL ON iso-db).

src/metabase/driver/mysql.clj:1293-1336

Make the test mirror prod: input = bound on MySQL

Four call sites at driver_isolation_test.clj L321 / L617 / L685 / L808 set in-schema = "mb_iso_in_<run>". For :mysql (and MariaDB, which uses the mysql driver), make that in-schema = (-> database :details :db) — the bound DB. Source tables get created in the bound DB with per-run names; the grant runs on bound; mysql.db gets the row; handshake passes.

Skip create-input-namespace-sql / drop-input-namespace-sqls on MySQL (bound DB already exists; don't create or drop it). Replace with explicit per-table DROP TABLE IF EXISTS cleanup.

enterprise/backend/test/metabase_enterprise/workspaces/driver_isolation_test.clj

Don't touch grant-workspace-read-access!

Already correct on MySQL — grants SELECT ON <db>.* for whatever DB list it receives. With the test fix, the list contains the bound DB, and the right mysql.db row gets written.

src/metabase/driver/mysql.clj:1350-1361

why mirroring prod is the right call Tests should exercise the wire shape the product actually ships. The fresh-input-namespace divergence has a legit reason on Redshift, none on MySQL. Aligning the test with the canonical config file removes the bug, removes the wrong "USAGE saves us" code, and removes the test's claim that MySQL supports an unsupported config (input ≠ bound). Net: ~10 lines removed in mysql.clj, ~20 lines changed across 4 test sites, no production behavior change.
