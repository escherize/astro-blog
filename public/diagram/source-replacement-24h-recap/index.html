What's Being Built

An enterprise feature that lets Metabase admins swap one data source for another across all dependent questions and dashboards. From the Dependency Graph panel, users select a source table/model, pick a replacement target, review column compatibility, and launch an async background job that rewrites every card that references the old source.

Compatibility Check
Validates column mappings, detects type mismatches, FK changes, PK drift, cycle detection, and cross-database errors — before any writes happen.
Two-Phase Swap
Phase 1: Upgrade all transitive dependents' field refs to modern pMBQL. Phase 2: Rewrite direct dependents to point at the new source.
Async Execution
Runs in a virtual thread with DB-backed progress tracking. Frontend polls every second. Supports cancellation and 30-minute timeout via Quartz job.
Enterprise Gating
Plugin-gated behind the dependencies premium feature. OSS gets a placeholder stub. UI entry point lives in the Dependency Graph panel header.

Database migration detail
New table: source_replacement_run — tracks async replacement jobs. Uses the nullable unique boolean pattern for is_active: only one row can have is_active = true at a time, enforcing a single active run cluster-wide without a distributed lock. Columns include status (started/succeeded/failed/canceled/timeout), progress (0.0–1.0), source_entity_type/id, target_entity_type/id, timestamps, and user_id FK.

Iteration & Churn

This is classic WIP development — the API shape and component structure were discovered through building. Some notable back-and-forth:

Areas of Churn
  • format-column changed 5+ times — oscillated between database_type, base_type/effective_type, nested FK target info, then back to flat with u/qualified-name for serializing type keywords
  • ErrorsCell / NameCell renamed back and forth — settled on ErrorCell and NameCell as final names
  • replacement/utils.ts deleted and re-created — initially in utils.tsx, extracted to utils.ts, deleted, then brought back with error message helpers
  • Error taxonomy evolved — started as per-column only, then split into entity-level + column-level with separate helper functions and default fallbacks
  • Response schema reshaped — errors moved from per-mapping to top-level, column_mappings became optional, source/target in each mapping became required
Why so much churn? The API contract between backend and frontend was being negotiated in real-time. Alexander was simultaneously writing the backend validation in source.clj and consuming it in the React modal — a tight feedback loop where each iteration revealed what the UI actually needed from the response.
