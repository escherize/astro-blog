Harbormaster · Robo-Data-Engineer · Tech brief

The Control Plane we're building inside Harbormaster

A control plane that provisions disposable agent boxes — each one a Metabase EE instance plus an AI data-engineering agent — on demand, one per session, in our own EKS. The frontend never touches a box; everything flows through Harbormaster.

Scope: 3 verbs — provision · deprovision · message Runtime: EKS pod (cold boot) App-db: one shared PG, db-per-session Stage: internal demo

01 The shape of it

UI → Harbormaster control plane → supervisor → sandbox box. Comms are pull-based: the box long-polls the control plane; the box never receives inbound calls for the agent loop. The box reaches the data warehouse directly over the VPC.

02 The minimal API

Huddle-locked core (Bryan + Sasha, 6/15). PR creation deferred. Everything below is what the UI builds against; sandbox-callbacks (poll/events/heartbeat/scm-credentials) are dialed by the box, never the browser.

POST
/sessions

Provision a box for a project. Writes a Metabase CRD, derives the branch, returns {session-id, status:"creating"}.

POST
/sessions/:id/message

Send a prompt. The supervisor delivers it to the box; the agent's work streams back as events on the read channel.

DELETE
/sessions/:id

Deprovision: tear down the box + archive the session. Plus drop the workspace (teardown rule, §5).

read surface

How the UI sees the work

  • GET /sessions/:id — status, branch, preview URL, messages
  • GET /sessions — active session list
  • Event stream — text/tool deltas, completion, entity refs, git pushes
  • Transport: long-poll/SSE for demo (no WS layer in HM yet), WS later
recipes

Projects & models

  • GET/POST/PUT /projects — a recipe = owner/repo + warehouse conns
  • PUT/DELETE /projects/:id/databases — warehouse connections
  • GET /models — model catalog for the composer
  • Sessions always run for a project

03 Session lifecycle

Create → ready → running → deprovision. The supervisor streams every event into HM's database; the read channel replays it to the UI.

05 Multi-tenancy & the teardown rule

the hard part

Single-tenant → multi-tenant

The prototype is single-tenant; HM is multi-tenant. Every project / session row carries a tenant_id; reads scope to the caller's tenant. HM's org → subscription → quota → per-namespace isolation is the substrate we slot under. This is the bulk of the HM-side effort.

correctness

The teardown rule

Workspaces provisions an isolated schema + scoped warehouse user that live in the warehouse, not the box. Killing the pod does not drop them.

Rule

Any phase that adds workspace provisioning must add workspace deprovisioning in the same change. Otherwise every session silently leaks a schema + user into the shared warehouse.

Why db-per-session beat schema-per-session

Both are one shared Postgres pod. Database-per-session keeps native CREATE DATABASE … TEMPLATE instant clones, stronger isolation (separate catalog, grantable per-db role), and zero new code (existing local-postgres provider). Schema-per-session has no native schema TEMPLATE and weaker isolation — it'd only win at a database-count ceiling we won't hit at ≤5 concurrent / ≤20 a day.

06 What the supervisor streams into

New requirement: the supervisor streams session data into HM's Postgres. So HM needs tables, not just fire-and-forget pods.

session_event is append-only and cursor-ordered — it powers both the replay stream and the audit trail. The box's app-db (database-per-session) is separate from this and lives in the shared PG pod.

07 Held back, on purpose

Sasha's gap report mapped the genuinely hard parts metabot-app already solved. They're the risk map, not the build order. Build the 3 verbs first; these are fast-follow once the loop works end-to-end.

Golden-image bake

Snapshot + ~15s restore. A scale-fork optimization; demo cold-boots fine.

Pause / idle / lifetime / health sweeps

Cost + liveness machinery. Needed at scale, not for a 5-box demo.

WebSocket coordinator

Live multiplayer + presence. Long-poll covers the demo.

Generation-aware restore

App-db schema/version matching on resume. Couples to the bake pipeline.

Two-repo git sync

Bare sync.git + working clone + ephemeral credential broker. Port when git matters.

Cost accounting

Per-session spend. HM's quota framework makes it nearly free — later.
