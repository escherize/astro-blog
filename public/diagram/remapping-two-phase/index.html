Two-phase remapping, or how queries find their way

A workspace child instance must read from ws_alice.public__orders when its queries reference public.orders. The rewrite happens in two passes through the query processor: a metadata swap during preprocess for MBQL, and an authoritative SQL rewrite after compilation for everything. The second pass is what makes the security boundary real.

What each phase does

why two and not one

1
Preprocess — MBQL metadata swap
Walks the cached metadata provider. For each table that has a :model/TableRemapping row, it overrides :schema and :name in place so HoneySQL emits workspace identifiers downstream. Cheap. Skips native. Native SQL at this stage may still contain unresolved {{snippet: foo}}, {{#42}}, and template tags — touching it now would be premature.
2
Post-compile — authoritative SQL rewrite
Runs in execute.clj middleware after every other preprocess step. By now the SQL is a single string with no unresolved bits. Parses it with sql-tools/replace-names (SQLGlot under the hood), walks the AST, rewrites every table ref, re-emits. Catches both MBQL and native. Throws ex-info on parse failure — the query never executes against the warehouse.

Why post-compile, not preprocess
A naive design would parse SQL during preprocess and rewrite it there. That fails because template tags, snippet placeholders, and card references aren't valid SQL — SQLGlot will choke or misparse. The principle: resolve everything that affects identifiers before parsing. Phase 2's placement guarantees the SQL is final.
Why we throw, not fall back
The whole point of remapping is workspace isolation. If Phase 2 can't parse a query, the safe behavior is refuse to run it — surfacing a clear error to the user. Falling back to "run the original SQL" would silently breach isolation and let a workspace child instance touch production tables. Fail closed, never open.
Free escape hatches
Phase 2 short-circuits to a no-op when enabled-for-db? returns false (no remappings for this database) or when *skip-remapping?* is bound. The latter is for display-only callers like POST /api/dataset/native that want users to see the SQL they wrote, not the rewritten form. Never bound on an execution path.
