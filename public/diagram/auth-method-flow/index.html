How auth_method Flows to Analytics

login -> session -> middleware -> view_log / query_execution

Every request in Metabase carries an auth_method value that records how the user authenticated. This value flows from login through session middleware into the *auth-method* dynamic var, and lands in view_log and query_execution rows via include-sdk-info.

Provider String Values

The auth_identity.provider column stores these values as strings. They come from (name :provider/xxx) in auth_identity/provider.clj.

Provider Keyword Stored String Auth Type Source
:provider/password "password" Built-in Email/password login
:provider/ldap "ldap" SSO LDAP directory auth
:provider/jwt "jwt" SSO JWT token auth (enterprise)
:provider/saml "saml" SSO SAML SSO (enterprise)
:provider/google "google" SSO Google OAuth
:provider/oidc "oidc" SSO OpenID Connect
:provider/custom-oidc "custom-oidc" SSO Custom OIDC provider
:provider/slack-connect "slack-connect" Integration Slack Connect
- "api-key" Special Hardcoded in session-tracking-mw, no auth_identity row API key auth bypasses session creation entirely
- "session" Fallback Legacy sessions without auth_identity_id Older sessions created before auth_identity tracking was added

Critical Code Paths

auth_identity/provider.clj - create-user! (line ~330) and update-user! (line ~310) insert rows into auth_identity with provider = (name provider-keyword). This is where the string value originates.
auth_identity/session.clj - create-session-with-auth-tracking! (line ~15) looks up the auth_identity row by user_id + provider, then creates a session with auth_identity_id as a foreign key.
server/middleware/session.clj - The session-with-id query (line ~105) LEFT JOINs auth_identity to get provider AS auth-provider. Then merge-current-user-info puts it on the request map. Finally, session-tracking-mw binds *auth-method*.
analytics/sdk.clj - include-sdk-info (line ~93) copies *auth-method* into the row map as :auth_method. Called by both view-log and query-execution insert paths.

Writing SSO auth_method Tests

You do not need a real JWT/LDAP/SAML server to test auth_method values. Create an AuthIdentity row directly with mt/with-temp, then create a session linked to it. The middleware will pick up the provider from the JOIN.

Test Pattern - Direct auth_identity insertion
;; Create a user + auth_identity + session manually
(mt/with-temp [:model/User {user-id :id} {}
              :model/AuthIdentity {ai-id :id}
                {:user_id    user-id
                 :provider   "jwt"    ; <-- the value you're testing
                 :auth_hash  "test-hash"}]
  ;; Create session linked to this auth_identity
  (let [session (auth-identity.session/create-session-with-auth-tracking!
                  :provider/jwt user-id "127.0.0.1")]
    ;; Make a request with this session
    ;; The middleware will LEFT JOIN auth_identity
    ;; and bind *auth-method* = "jwt"
    ;; Then view_log/query_execution will capture it
    (is (= "jwt" (:auth_method (t2/select-one :model/ViewLog
                                              :user_id user-id))))))
Watch out: create-session-with-auth-tracking! looks up the auth_identity by (user_id, provider). If you create the AuthIdentity with provider = "jwt", you must pass :provider/jwt to the session creator so the lookup matches.
Alternative: bind *auth-method* directly (unit test style)

For unit tests that don't need the full middleware stack, you can bind the var directly:


(sdk/with-auth-method! ["jwt"] (let [row (sdk/include-sdk-info {})] (is (= "jwt" (:auth_method row)))))

This tests include-sdk-info in isolation but doesn't verify the middleware flow.

Special Cases

Scenario auth_method Value Why
API key request "api-key" Hardcoded in session-tracking-mw. No session, no auth_identity row. API keys use a separate auth path entirely
Legacy session (no auth_identity_id) "session" The LEFT JOIN returns NULL for provider, so the fallback kicks in. Sessions created before auth_identity tracking was added
No session at all (public/embed) nil No session middleware runs for these routes. *auth-method* stays nil.
