In-Situ Compilation Tracking

swap_verify — phase-boundary regression attribution for source replacement

When a source swap breaks card compilation, was it Phase 1 (field ref upgrade) or Phase 2 (source swap) that caused it? This system instruments the production runner with opt-in hooks that compile all cards at each phase boundary, attributing regressions to the exact phase responsible.

runner.clj — production swap_verify.clj — dev only

The Dynamic Var Pattern

A single ^:dynamic *compilation-tracker* var in runner.clj. Default: nil. Three (when *compilation-tracker* ...) guards around the two phases. When nil, the when short-circuits — zero overhead. When bound by swap_verify, every card gets compiled three times.

;; runner.clj
(def ^:dynamic *compilation-tracker*
  "Called at :before-upgrade, :after-upgrade, :after-swap"
  nil) ;; nil = zero overhead in production

Phase Boundary Compilation

At each hook point, the tracker compiles every card entity and stores a snapshot. Then diffs adjacent snapshots to find regressions — cards that compiled before but fail after a given phase.

The Closure Pair Pattern

make-compilation-tracker returns [callback-fn, results-atom]. The callback captures the atom in its closure. The caller binds the callback, runs the swap, then derefs the atom to read results.

;; swap_verify.clj
(let [[tracker-fn tracker-results] (make-compilation-tracker)]
  (binding [runner/*compilation-tracker* tracker-fn]
    (runner/run-swap old-source new-source))
  ;; tracker-results is an atom, deref after the run
  (let [data @tracker-results] ...))
Results atom shape
{:regressions
  {:upgrade [{:card-id 123 :card-name "..." :error {...}}]
   :swap    [{:card-id 456 :card-name "..." :error {...}}]}
 :stats
  {:before-upgrade {:compilable 45 :failing 3}
   :after-upgrade  {:compilable 44 :failing 4}
   :after-swap     {:compilable 42 :failing 6}}}

Entry Points

run-verified-swap!
Single-card verified swap. Creates tracker, binds it, runs runner/run-swap in a rollback transaction. Prints structural, compilation, metadata, and column stability checks plus a new "Phase Attribution" section showing which regressions came from upgrade vs swap.
run-swap-bench
Takes [{:card-id N :dep-count M} ...]. Checks actual dep count before choosing a filename — if actual < expected, skips entirely (no files written). Only qualified cards appear in the filename. Writes paired output files:
run_<sha>_<ids>_<date>.log — captured console + log4j
run_<sha>_<ids>_<date>.edn — structured vector of per-card reports
bench-entries
Helper: takes [card-id ...], queries live dep counts from the DB, returns [{:card-id N :dep-count M} ...] ready for run-swap-bench.

Tricks We Used

Trick 01
Zero-cost instrumentation
(when *compilation-tracker* ...) in runner.clj. The nil check short-circuits — no function call, no allocation. Only active when swap_verify binds it.
Trick 02
Closure pair pattern
make-compilation-tracker returns [fn, atom]. The fn captures the atom in its closure. Caller binds the fn, runs the swap, derefs the atom after. Clean separation.
Trick 03
Phase diffing
Each snapshot is compared to the previous one, not the baseline. So upgrade regressions are separated from swap regressions. The diff only records cards that regressed (compiled before, failed after).
Trick 04
Dep count guard
Check actual vs expected dep count before choosing a filename. If deps shrank, skip the card entirely — no files created, no previous good data overwritten.
Trick 05
Log/EDN split
Same base name, different extensions. .log for humans (captured stdout+stderr). .edn for machines (pprinted structured data). They line up in ls.
Trick 06
binding vs requiring-resolve
binding resolves vars at compile time. If the runner namespace was loaded before the var was added, it fails. requiring-resolve returns nil for missing vars → NPE in with-bindings. Fix: reload runner first, use plain binding.
Why 3x compilation overhead is fine. The tracker compiles all cards once per phase boundary (3 times total). This ~triples the compilation cost. But it only activates when swap_verify explicitly binds the var — it's a diagnostic tool. In production, *compilation-tracker* stays nil and the when guards cost essentially nothing.
