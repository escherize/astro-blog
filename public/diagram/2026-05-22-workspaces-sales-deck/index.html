01

The problem

Production is a crowded room.

Today

Analysts share one warehouse.

  • One slip and you've overwritten the schema everyone depends on.
  • Modeling work happens in spreadsheets, then gets rebuilt by data engineers.
  • AI agents write SQL faster than humans — and against the same production tables.
02

The idea

Give every analyst their own room.

A Workspace is…

A private copy of Metabase pointed at a private corner of your warehouse.

  • Same data sources, scoped down.
  • Reads production. Can only write to its own sandbox.
  • Lives on the analyst's laptop, not in the shared environment.

What engineers already have

Git branches.

Every developer gets their own branch. They build, break, and rebuild safely. Code only reaches production through review.

  • Isolated copy of the codebase
  • Test freely without affecting others
  • Merge back via pull request

What analysts get now

Workspaces.

Every analyst gets their own sandbox. They model, test, and iterate — alongside an AI agent if they want. Changes only reach production through review.

  • Isolated copy of the warehouse view
  • Build models freely without affecting others
  • Merge back via the same git workflow
03

How it feels

A link, a command, a pull request.

Why it's safe

The safety net is structural.

Built-in guardrails

What the sandbox actually prevents.

0
Writes to production
The sandbox user literally lacks permission to touch your canonical tables.
1:1
Workspace per analyst
No two analysts share a sandbox. No two sandboxes share a writeable namespace.
∞
AI retries, zero risk
Let an agent regenerate SQL all day. Worst case: a broken sandbox table. Production is untouched.
Git
Review before merge
Every change to production schemas is a pull request. Approve, reject, or comment — like code.
