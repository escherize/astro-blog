Why this exists

The dependency graph was only reachable through models.dependency — i.e. only via DB queries. The checker module operates on exported YAML with no live AppDB, so it could not query the dependency graph at all. This PR extracts two protocols so both contexts share an API.

03

Protocol surface

All graph queries return {entity-type #{ids}}, e.g. {:card #{1 2} :table #{3}}.

Protocol Method Purpose Kind
Store store-deps! Replace ALL outgoing edges for [entity-type entity-id]. Input shape matches deps.calculation/calculate-deps output. mutate
Store delete-deps! Remove ALL outgoing edges for an entity. No-op when none exist. mutate
Store graph Return a DependencyGraph for querying current edges. In-memory variant returns a point-in-time snapshot. read
Graph direct-upstream What this entity depends on (immediate parents). read
Graph direct-downstream What depends on this entity (immediate children). read
Graph transitive-upstream All transitive ancestors. Excludes the entity itself. read
Graph transitive-downstream All transitive descendants. Excludes the entity itself. read
Graph find-cycle If entity sits inside an upstream cycle, returns the cycle as [[:card 1] [:card 2] [:card 1]]. Nil if none. read

Dynamic *store* defaults to the DB-backed impl. Eager root binding → constructor must stay cheap.

In checker/semantic.clj a new build-dependency-store walks the checker's entity cache and populates a fresh in-memory store via deps.calculation/calculate-deps: 

(defn build-dependency-store [checker-store]
  (let [dep-store (deps.store.mem/in-memory-dependency-store)]
    (doseq [kind (disj deps.dependency-types/dependency-types :table)
            eid  (store/all-refs checker-store kind)
            :let  [raw (store/cached-entity checker-store kind eid)]
            :when raw]
      (try
        (let [deps (deps.calculation/calculate-deps kind raw)]
          (deps.store/store-deps! dep-store kind (:id raw) deps))
        (catch Exception e
          (log/warnf e "Failed to calculate deps for %s %s, skipping" kind eid))))
    dep-store))
05

Design note — the graph tells the truth

DependencyGraph is intentionally unfiltered. It returns the complete dependency graph regardless of who is asking.

Today's API endpoints in dependencies/api.clj bake permission filters into the graph walk and silently drop invisible nodes and their entire subtrees. If card X depends on invisible card Y depends on table Z, the user sees X with no dependencies. That hides real impact.

Intended migration:

  1. Graph protocol stays pure and complete (this PR).
  2. A presentation layer annotates nodes with visibility, surfaces hidden-node counts, and preserves transitive impact through invisible intermediaries.
  3. Walk-time options (e.g. skip native cards for metadata updates) are graph semantics, not access control — added as options to the transitive-* methods when needed.

Test strategy

A shared contract harness parameterized by store factory runs the same 22 tests / 288 assertions against both impls. In-memory-only tests cover topologies that would be painful with DB fixtures.

200-node ring

Stress-test cycle detection & transitive walks over a maximal cycle.

Diamond deps

Shared upstream ancestor — verifies dedup in transitive results.

100 concurrent writers

Atom semantics + bidirectional swap! hold under contention.

Snapshot isolation

(graph store) is point-in-time; writes after capture don't bleed into the snapshot.

(deftest cycle-detection-test
