1 — Overview
What Changed
source_swap.clj previously only had one operation: upgrade — converting ID-based field refs to name-based ones. The enterprise source.clj had its own duplicate column-matching logic.

Now source_swap.clj has two operations, column comparison logic lives in the shared lib, and the enterprise layer is a thin API wrapper.
2 — Core Concept: Upgrade vs Swap
Upgrade (existing, refined)
Swap (NEW)
ID → Name
;; before [:field {} 42] ;; after [:field {} "COLUMN_NAME"]
Converts integer field IDs to name-based refs by resolving against visible columns. Safe and idempotent. Skips already-upgraded and implicitly-joined refs.
Old ID → New ID
;; before (orders.id) [:field {} 42] ;; after (products.id) [:field {} 99]
Replaces source table/card and remaps all field IDs in a single pass using a prebuilt mapping. Also handles :source-field (implicit joins) and parameter targets.
Why both? — Upgrade is a preparatory step that makes queries portable (name-based refs survive source changes). Swap is the actual replacement operation that rewrites a query to point at a different table or card. They compose: upgrade first to stabilize refs, then swap to change the source.

10 — Design Decisions
Architectural Choices
  • Upgrade vs Swap separation — Upgrade converts to name-based refs (safe, idempotent). Swap does direct ID remapping. They serve different purposes and compose.
  • Guard predicates — should-upgrade-* avoids expensive column resolution when nothing needs upgrading. Uses match-lite for fast clause scanning.
  • field-id-mapping as data — The mapping {old-field-id → new-id-or-name} is built once and threaded through. Table→table maps to IDs; table→card maps to column alias strings.
  • Enterprise → lib_be migration — Column comparison logic moved to shared lib so it's testable and reusable outside the enterprise replacement API.
  • Bulk metadata loading — all-referenced-entity-ids + bulk-load-query-metadata = one scan + one batch load instead of N individual lookups per entity.
What's next? — The swap operation is now in lib_be but the enterprise execution layer (execute.clj, runner.clj) hasn't been updated to call it yet. These commits establish the foundation; wiring it into the actual replacement flow is the next step.
