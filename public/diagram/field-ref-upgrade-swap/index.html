Field Ref Upgrade + Source Swap

why they must be a single, source-aware operation

PROBLEM Separate upgrade then swap breaks refs

If we upgrade field refs first (making them name-based for Model B), then swap Model B for Table C, Question A ends up with [:field "PRICE" ...] pointing at a table — but tables expect ID-based refs like [:field 42 ...]. The refs are now in the wrong format.

[:field 42 ...]"]

[:field #quot;PRICE#quot; ...]"]:::upgraded
            B1x["Model B"]
            A1x -->|"source"| B1x
            A1 -.->|"upgrade refs"| A1x

[:field #quot;PRICE#quot; ...]"]:::upgraded

pointing at table"]:::errorNode
          end

SOLUTION Normalize twice: before and after swap

Alexander's insight: the "upgrade" function is really a normalize-to-what-the-source-expects function. Models expect name-based refs. Tables expect ID-based refs. Run it twice — once with the old source, once after setting the new source — and refs always end up correct. 

        graph TD
          start["Question A
[:field 42 ...]
source: Model B"]

          subgraph phase1 ["Phase 1: Normalize for old source"]
            norm1["normalize_refs(Question A, Model B)"]
            result1["Question A
[:field #quot;PRICE#quot; ...]
source: Model B"]:::modelState
          end

          subgraph swap ["Swap source"]
            doswap["Set source = Table C"]
            mid["Question A
[:field #quot;PRICE#quot; ...]
source: Table C"]:::midState
          end

          subgraph phase2 ["Phase 2: Normalize for new source"]
            norm2["normalize_refs(Question A, Table C)"]
            result2["Question A
[:field 42 ...]
source: Table C"]:::tableState
          end

          start --> norm1
          norm1 --> result1
          result1 --> doswap
          doswap --> mid
          mid --> norm2
          norm2 --> result2

MATRIX All swap scenarios

The normalize function handles every source type combination. The ref format always matches whatever the new source expects.

Old Source New Source After Phase 1 After Phase 2 Result
Model Model [:field "PRICE" ...] → [:field "PRICE" ...] Stays name-based
Model Table [:field "PRICE" ...] → [:field 42 ...] Downgrade to ID
Table Model [:field 42 ...] → [:field "PRICE" ...] Upgrade to name
Table Table [:field 42 ...] → [:field 99 ...] Stays ID-based
The insight: "Upgrade" is a misnomer — it's really normalize_refs(query, source). It resolves refs to whatever format the given source expects. By running it twice (old source, then new source), the swap operation becomes a single unified function that handles all four source type combinations correctly. Field ref format is always an emergent property of the source type, never an independent concern.
