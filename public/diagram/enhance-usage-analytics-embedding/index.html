Enhance Usage Analytics for Embedding

branch: enhance-usage-analytics-for-embedding · EMB-1500 through EMB-1535

Metabase's embedding customers lack visibility into how embedded content is used. This project extends view_log and query_execution with richer context - auth method, tenant, GDPR-sensitive request metadata, and security flags - then exposes everything through updated analytics views. The goal: power an Embedded Analytics dashboard showing usage trends, tenant activity, and content popularity.

Why auth_method is bound in session middleware, not embedding middleware: embedding-mw runs before authentication resolves. merge-current-user-info is where session vs API key is distinguished - we tag the request there, then bind-current-user binds the dynamic var.

Design Decisions
architecture Single chokepoint
Both ViewLog and QueryExecution Toucan before-insert hooks call include-sdk-info. PII extraction added there - zero changes to call sites. The function is idempotent (double-call in QE path is harmless).
privacy GDPR gate at write time
Setting check happens when the row is written, not in middleware. Toggling takes effect on the very next write - no restart or cache clear needed.
dependency ip-address to request.current
Broke circular dep: sdk -> request.util -> analytics.core -> sdk. request.current has zero analytics deps. request.util/ip-address delegates.
pattern is_impersonated via rff
Can't set in query-execution-info because impersonation resolves during QP preprocessing (after info capture). Follows existing is_sandboxed pattern - rff wrapping in EE impersonation middleware sets it on result metadata.
simplicity is_db_routed is pre-pipeline
destination-database-id IS available in query-execution-info (set by attach-destination-db-middleware in preprocessing). Simple (boolean destination-database-id).
read-time Surface derived in views
CASE expression in analytics views maps embedding_client to human-friendly surface values. If mapping evolves, historical data updates automatically.
