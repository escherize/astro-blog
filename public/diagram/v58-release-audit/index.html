How to Verify (git commands)
Each issue was verified by searching the release branch commit log. You can reproduce any of these checks:
git log origin/release-x.58.x --oneline --grep="ISSUE_NUMBER"
For example:
git log origin/release-x.58.x --oneline --grep="69900"
Returns: 5d641700632 backported "Capitalize Jar -> JAR" (#69909)

The issue number appears in the commit message body or referenced PR, even though the commit's primary (#NNNNN) tag is the backport PR number.
Pattern Breakdown - Why 13 of 16 are backport-related
Backport PR mismatch (10 issues): The automated backport bot creates a new PR for each backport. The commit on the release branch references this new PR number, not the original issue. The milestone checker traces commit → backport PR → finds no linked issue in the milestone.

Commit format issues (4 issues): The [58] prefix, Manual Backport: prefix, or dual PR numbers in the commit message may cause the parser to fail to extract the correct PR number.

Indirect reference (1 issue): #68998's commit is a backported test fix for the issue, not the issue fix itself. The commit message mentions the issue number in the description but not as the PR reference.

Wrong version (1 issue): #69922 is a v0.57 security fix that appeared in the v0.58.8 check results.
