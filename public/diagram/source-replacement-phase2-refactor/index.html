Phase 2 Refactor

source replacement → lib-be source-swap APIs

Phase 2 of source replacement (the actual source swap for direct dependents) previously used a hand-rolled field_ref_update.cljc for MBQL swapping and custom field-ref matching in viz.clj. This refactor replaces both with three focused lib-be.source-swap functions, deletes 140 lines of field-ref-update code, and adds coverage for second-level dashboard dependents.

Second-Level Dashboard Problem new

The scenario: Table T is the old source. Card A depends on Table T. Dashboard D contains Card A with a filter parameter mapped to [:field {} field-from-T]. Dashboard D is not a direct dependent of Table T — it's a direct dependent of Card A. When Card A's source is swapped, D's parameter targets still point at old field IDs.

The build-swap-field-id-mapping function only returns a mapping for table→table and table→card swaps (nil for card→card), which naturally gates the second-level dashboard processing.
