01 · FAILURE

ClickHouse — CREATE SCHEMA is a syntax error

ClickHouse calls its top-level namespace a "database," not a "schema." The standard CREATE SCHEMA <name> SQL parses on every other warehouse but bombs on the CH side.

java.sql.SQLException: Code: 62. DB::Exception: Syntax error: failed at position 8 (SCHEMA): SCHEMA `canonical_schema_56cf7d14`. Expected one of: OR REPLACE, TEMPORARY, TABLE, DATABASE, sql security, DEFINER, SQL SECURITY, MATERIALIZED, VIEW, DICTIONARY, LIVE, WINDOW, USER, ROLE, QUOTA, POLICY, ROW POLICY, SETTINGS PROFILE, PROFILE, FUNCTION, WORKLOAD, RESOURCE, NAMED COLLECTION, UNIQUE, INDEX. (SYNTAX_ERROR)
Site
e2e_test.clj:146 → create-canonical-schema!
Driver
:clickhouse
Cause
Helper fell through to the generic CREATE SCHEMA branch on ClickHouse instead of dispatching to CREATE DATABASE.
Fix
Add an explicit :clickhouse case to the case dispatch that emits CREATE DATABASE. Mirror change in the teardown drop-canonical-schema! (which was already CH-aware on the drop side).
02 · FAILURE

SQL Server 2022 — LIMIT 1 is not T-SQL

SQL Server uses TOP n in the SELECT clause; LIMIT 1 tacked on the end parses as garbage near the bound parameter.

com.microsoft.sqlserver.jdbc.SQLServerException: Incorrect syntax near '1'. SQLState: S0001 errorCode: 102 at metabase-enterprise.workspaces.e2e-test/fn/fn/fn/fn e2e_test.clj:218
Site
e2e_test.clj:218 — source-table probe inside list-warehouse-tables-in-schema branch
Driver
:sqlserver
Cause
Probe SQL appended LIMIT 1 on a portability-shared code path. Fine on Postgres / MySQL / ClickHouse; rejected by T-SQL.
Fix
Drop the LIMIT 1. The probe only needs to fail-or-succeed against an EXISTS-style check, not return a single row, so the limit was load-bearing for nothing.
